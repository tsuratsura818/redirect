PIVOLINK SPEC

PivoLinkの仕様 — 本件で使う機能

PivoLinkは「印刷済みのQR・設置済みのNFCタグの遷移先を、後から変えられるようにする」自社SaaS（本番稼働中・redirect.tsuratsura.com）。自販機のように一度貼ったら剥がせないQRとの相性が、そのまま価値になります。

遷移ルール（設定できる条件）と本件での使い道
schedule期間指定／キャンペーン期間中だけ抽選ページへ。期間外は自動で対象外
scheduled_switch日時で切替／開始前＝ティザー、終了後＝終了ページへ無人で移行
time_of_day時間帯（JST）／時間帯別に訴求を変える
scan_step読取回数／1回目は案内つき、2回目以降は抽選ページへ直行
deviceiOS／Android／PC別の出し分け
ab_test重み付きA/B／クッションページの文言・ボタンの勝ち負けを実測する
defaultいずれにも当たらないときの既定の行き先
設計上の注意（実運用で踏んだ事実）：ルールは組み合わさらず、上から順に最初に当たった1つだけが有効になります。時間帯ルールで1日を覆うとA/Bテストが一度も発火しません。本件では期間ルールを主軸に据え、下位ルールに落ちる余地を意図的に残した設計にします。
本件で効く機能
貼り替えゼロで行き先が変わるシールは一度きり。開始前・期間中・終了後・期間延長・抽選サービスの乗り換え・緊急停止まで、すべて管理画面から
クッションページタイトル・本文・ボタン文言・ロゴ・背景色・文字色・アクセント色・表示秒数・クーポンコードを設定可能。規約提示や注意喚起の面として使う
スキャン解析日時・デバイス種別・OS・ブラウザ・地域・参照元を記録。QR単位で集計し、CSVで出力できる
変更履歴が残るいつ誰がどこへ向き先を変えたかの記録。運用ミスを追跡できる
QR画像を自動生成PNG／SVGで出力。SVGなのでシール印刷の入稿にそのまま使える
Businessプランは発行数・アクセス数とも無制限¥4,980/月。台数が増えても費用が跳ねない

USE CASE 01 ／ エリア別計測

QRを5本発行すれば、5つのエリアが別々に見える

抽選ページは1つのままで構いません。入口のQRを5本に分けるだけで、エリアごとのスキャン数・時間帯・端末構成・抽選ページへの遷移率が、5本ぶん独立して取れます。シールのデザインも文言も同じ。変わるのはQRの絵柄だけなので、追加費用はほぼ発生しません。

北海道・東北エリア/r/cp-north
関東エリア/r/cp-kanto
中部エリア/r/cp-chubu
関西エリア/r/cp-kansai
九州・沖縄エリア/r/cp-kyushu

行き先は、5本とも同じ1つの抽選ページでよい

外部の抽選サービス側にエリア別の設定は要りません。応募ページを作り分ける必要も、契約を分ける必要もない。「入口を分ける」だけで計測が生まれるのが動的QRの構造です。

あとから「関東だけ別の景品ページへ」といった出し分けをしたくなった場合も、管理画面で該当QRの行き先を変えるだけで対応できます。

USE CASE 02 ／ 期間切替

同じQRのまま、期間ごとにキャンペーンを差し替える

QRが指しているのはPivoLinkの固定URLで、実際の行き先は管理画面が持っています。A期間とB期間で景品を変えても、シールの刷り直しも貼り替えも発生しません。切替日時を先に登録しておけば、当日の作業もゼロです。

MEASUREMENT

計測設計 — 発行の粒度を、最初に決める

発行したQRの数が、そのまま集計の単位になります。1本だけ発行すれば全国合計しか出ず、台ごとに発行すれば台ごとに出ます。あとから細かくすることはできないので、ここは着手前に決めておく必要があります。

発行の粒度と、得られるもの
粒度QR数見えるようになること
全国で1本1総スキャン数・時間帯・端末構成のみ
エリア別5〜数十地域差（P.07の例）。5本発行すれば5エリアが別々に出る。ここが費用対効果の最初の山
ロット別数十〜数百設置ロット単位の反応。印刷・設置の手間と解像度の折り合いが良い
ロケーション別数百〜駅・オフィス・工場など立地タイプ別の効き方
台別設置台数分1台ごとの成績。貼り替え・撤去の判断に直結する

シールは粒度ごとに版が変わります。台別にすると印刷は可変データ印刷になり、貼付時に「どのシールをどの台に貼ったか」の台帳が必要です。まずはエリア別（5本）から始めるのが最も費用対効果が高く、次回にロット別・台別へ細かくしていくのが安全です。QRの発行そのものに追加費用はかかりません（Businessプランは発行数無制限）。

取れる数字と、その使い道
スキャン数（QR別・日別・時間帯別）設置台数で割れば「1台あたり何回読まれたか」。立地の良し悪しがここで出る
クッション → 抽選ページの遷移率読んだのに応募に進まなかった割合。文言・ボタン位置のA/Bで改善できる、唯一こちらで動かせる数字
端末・OS・地域・参照元年齢層の推定と、告知が効いた経路の把握に使う
外部サービスの応募数との突合スキャン → 遷移 → 応募 の3段で転換率が出る。翌年の予算配分の根拠になる
正確に申し上げておくと：PivoLinkのスキャン計測はブラウザ単位（Cookie／端末情報ベース）で、個人単位の厳密なユニーク数ではありません。同一人物の複数回スキャンや別端末は分離できません。「何人が」ではなく「何回・どこで」を測る仕組みとお考えください。人単位の数字は外部の抽選サービス側にあります。
