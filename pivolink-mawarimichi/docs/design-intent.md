# デザイン意図書 — Pivolink まわりみち 企画提案書

対象: `docs/pivolink-kyoto-proposal.html`（A4横17枚）
最終更新: 2026-08-03

このドキュメントの目的は、**企画書の見た目の判断を全部「なぜそうしたか」で説明できる状態にしておくこと**。
色や余白を変えるときは、まずここを更新してから手を動かす。

## 2. ターゲット設計 ★2026-08-03 確定

**主たる発注者: 観光協会・地域DMOの事業担当者**（他は副次的な読み手に降ろす）

| | 内容 |
|---|---|
| 読む人 | 事業担当。**決裁者ではなく起案者** |
| 決裁ルート | 担当が起案 → 事務局長・理事会 → 年度事業計画の枠に入るか |
| 動く理由 | 既存事業（スタンプラリー）の置換として説明できる／会員店・加盟店への送客が説明できる／運用の手間が増えない |
| 動かない理由 | 説明できない・年度計画に載らない・手間が増える |
| 意思決定様式 | 合議・年度単位。熱ではなく**説明可能性**で動く |

**この資料の唯一の仕事: 実証実験パック（3ヶ月・¥300,000）の発注を決めさせること。**

副次的な読み手（自治体・広域DMO／商店街・商工会／鉄道・交通事業者）には料金表とロードマップで応答する。
ただし**紙面の主語は観光協会・DMO**に固定する。全員に向けた資料は誰にも刺さらない。

## 6. 意図的にやらなかったこと ★

- **緑をベタ面に敷いていない。ピクトグラムも置いていない。**
  緑の資料は SDGs 提案に読まれやすく、そう読まれた瞬間に「環境の話」に矮小化される。
  この提案は環境の話ではなく**混雑と送客の話**なので、緑は線と文字だけに閉じ込めた。
- **ゴールドの格式演出をやめた。** 旧デザインは金 `#E5C84B` を多用していたが、
  「京都だから金」は根拠になっていない。説明できない色は落とした。
- **実在スポットの写真は使っていない。** 六波羅蜜寺ほか8箇所は**許諾未取得**のため、
  実写もAI生成も「その場所の写真」としては載せない。
  2026-08-03に写真を2枚だけ追加した（表紙＝早朝の路地／CONCEPT＝飛石と苔）。いずれも
  **場所を特定できない質感の絵**で、画面上に「イメージ（AI生成）— 特定の場所ではありません」と明記している。
  生成はMacのChatGPT定額枠経由（追加課金なし）。**2枚に絞ったのは、全ページに散らすと1枚も効かなくなるため**。
  参加者UIのスポット写真枠は「PHOTO PLACEHOLDER」のまま残し、現地撮影が入る位置であることを見せている。
- **「かわいそう」型・「盛り上がる」型の訴求をしていない。**
  読み手は理事会に諮る起案者。熱ではなく説明可能性で動くため、
  数字（6,279万人／1,268万人／補助率2/3）と構造で読ませている。
- **補助金の説明を主役にしていない。** 主たる読み手が観光協会・DMOなので、
  補助金は最終ページの補足に置き、主役は実証実験の発注に固定した。

## 7. 変えるときの手順

1. このドキュメントの §1〜§2 を先に更新する
2. 変わった前提から §5 の判断を引き直す（色だけ差し替えない）
3. コントラストを実測し直す（4.5:1 / 3:1 を割る配色は根拠があっても不採用）
4. 全ページが A4横（297×210mm）に収まっていることを確認する
   — 料金ページは元々123px はみ出して CTA が切れていた実績がある

## 8. TSURATSURA標準からの逸脱 ★次に触る人へ

`proposal-build` スキルの標準と**意図的に外している**点が2つある。知らずに「直される」のを防ぐために記録する。

| 標準 | 本件 | 外した理由 |
|---|---|---|
| §5 提案書は night `#1E2D3D` / gold `#E5C84B` / cream `#FDF8EF` / ultra `#2B4C8C` で統一 | 苔緑 `#3A5E4A` / 墨 / 白 / 朱 | 提案の後に参加者UIの実物デモを見せる。企画書とプロダクトの色が割れていると「別々に作られたもの」に見える。かつ「京都だから金」は根拠として説明できない |
| §3 RECOMMENDEDバッジは3プランなら真ん中 | 左端の実証実験パック `¥300,000` に付けた | 真ん中を推すのは客単価を上げるための一般則。本件は**資料の唯一の仕事が実証実験の発注**なので、バッジとCTAを一致させる方が優先 |

標準に戻す判断もありうる。**戻すなら §1〜2 の前提が変わったときだけ**にすること。

## 9. 5視点レビューの結果（2026-08-03）

| 視点 | 主な指摘 | 対応 |
|---|---|---|
| UX | **致命的**: 表紙に発行元・発行日が無い。フッターの `TSURATSURA / PIVOLINK` はモノスペースの刻印で社名として読まれない | 表紙下部に発行日＋社名を追加。宛名行はコメントで用意（提出先が決まったら外す） |
| ビジネス | **致命的**: 実証実験の「合格ライン」が無い。資料の仕事が実証実験の発注なのに、3ヶ月後に何が出れば成功かが書かれておらず、理事会で必ず詰まる | ROADMAP の Phase 1 に合格ライン4項目を追加（まわりみち率150%以上／8割のスポットにスキャン／1,000セッション・完走率50%／クーポン利用100件） |
| コピー | 「まわりみち率」が定義なしで使われている | 初出箇所に「（歩行距離÷最短距離）」を追記 |
| コピー | EXPERIENCE の1枚目が「VTuberコラボ」。理事会で最初に目に入る位置としてリスク | 01と03を入れ替え、本題（分散＝セレンディピティ）を先頭へ |
| テクニカル | OGP・canonical・JSON-LD・`<main>`が無い | 追加。エンティティ構文は CLAUDE.md の定義と一致させた |
| SEO/AEO | Organization + Service の JSON-LD | 追加済み |

### 未対応（判断が要るもの）

- **og:image が無い**。ホスティング先が未定のため作れない。SNS・Slackで共有すると無地のカードになる。本番URL確定時に 1200×630 を作る
- **TSURATSURA自身の実績・社会的証明がゼロ**。BUILD STATUS で「作れること」は示したが「これまで何を納品したか」が無い。正確な実績件数を確認のうえ1行入れるべき
- **課題（02 ISSUE）が統計からの一般論**。提出先が決まったら、4項目のうち1つを**先方が実際に言った言葉**に差し替える。ここが一般論のままだと「テンプレだな」と伝わる

4. 実績1行を入れる
5. 全ページがA4横に収まっているか実測で確認（`scrollHeight - clientHeight`）
