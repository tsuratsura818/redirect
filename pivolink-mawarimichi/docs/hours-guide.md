# 時間でルートを変える — 食べどきと営業時間

2026-08-18 実装。スポットに飲食店を足したときに、時間の扱いを2本立てで入れた。

---

## 1. 2つの軸を分けている理由

| 軸 | 意味 | 持ち方 | 効き方 |
|---|---|---|---|
| **食べどき** `meal_times` | その店が**向いている**時間 | `["lunch","dinner"]` | 帯の中 **2.0倍** ／ 帯の外 **0.25倍** |
| **開いている時間** `open_hours` | その場所が**開いている**時間 | `{"from":11,"to":21}` | 閉店中 **0.05倍** ／ 閉店1時間前 **0.4倍** |

同じ軸にすると両方壊れる。

- ランチの店は**夜も開いている**が、夜に薦める店ではない → 食べどきだけ落としたい
- 安井金比羅宮は**24時間入れる**が、向き不向きは無い → 開閉だけ常時OKにしたい

時刻→帯の対応（何時をランチとみなすか）は **`routing_rules.config`** にある。
店舗事情で変わる値なので、コードにもスキーマにも埋めていない。

```json
{ "meal_bands": { "morning":[7,8,9,10], "lunch":[11,12,13,14],
                  "snack":[14,15,16,17], "dinner":[17,18,19,20,21] },
  "meal_in_band": 2.0, "meal_off_band": 0.25 }
```

**閉店ペナルティが 0 ではなく 0.05 なのは意図的。** 0にすると、回廊内の候補が2件を切ったときに
フォールバックで結局出るうえ、全候補の重みが0になって抽選が壊れる。「まず出ない」で十分。

## 2. 効いていることの実測

清水寺行き・800周・時刻別の提示シェア（`npm run sim -- --meals`）。

| 時刻 | 喫茶 朝霧<br>(朝・おやつ) | 食堂 なゝかまど<br>(昼・夕) | 甘味 ひとやすみ<br>(おやつ) | 居酒屋 みやこ路地<br>(夕) |
|---|---|---|---|---|
| 8時 | **5.6%** | 2.5% | 8.8% | 2.8% |
| 12時 | 0.9% | **9.3%** | 9.1% | 2.4% |
| 15時 | 4.7% | 2.1% | **14.9%** | 2.3% |
| 19時 | 0.6% | **9.8%** | 8.4% | **9.7%** |

朝10時に居酒屋は出ず、昼に食堂が出て、15時に甘味処が出る。狙いどおり動いている。

## 3. ★実運用時間は 9:00〜16:00

営業時間を入れた結果、**朝夕は回遊自体が成立しない**ことが数字で出た。

| 時刻 | 開いているスポット | ユニークルート（3目的地の最小） |
|---|---|---|
| 7時 | 2 / 13 | — |
| 8時 | 4 / 13 | 396 ← 基準割れ |
| **9〜16時** | **8〜12 / 13** | **434〜809 ✅** |
| 17時 | 6 / 13 | 375 ← 基準割れ |
| 18〜21時 | 2〜3 / 13 | 271〜450 ← 基準割れ |

**19時に開いているのは3件しかない。** 5つ寄り道するには足りない。
これは仕組みの不具合ではなく、京都の寺社が17時に閉まるという事実そのもの。

**だから何をしたか**

1. 受け入れ基準（二択破綻0・ユニークルート400通り以上）は **9〜16時で判定する**ことにした
   （`tests/routing.test.ts` の `OPERATING_HOURS`）
2. 目的地選択の画面で、**開いている場所がスタンプ数に足りないときは先に伝える**。
   「歩けますが閉まっている場所に当たります。9:00〜16:00がいちばんよく巡れます」
3. 閉まっている目的地は、**選ぶ前に**「本日の拝観は終了しています」と出す
   （選べるようにはしてある。門前まで歩くこと自体は成立するので）

**実証実験の告知は「9:00〜16:00」と書くこと。** 17時開始のチラシを撒くと、
分散のために散らした先が全部閉まっているという、最短ルートより悪い体験になる。

夜も回したいなら、選択肢は2つ:
- 夜に開いている寄り道を増やす（居酒屋・商店街・ライトアップ・夜間拝観）
- 夜だけ `stamp_target` を減らす（3つに）

## 4. 管理画面での入れ方

**開いている時間** — 開く時 / 閉まる時 を入れる。**終日入れる場所（屋外の社・通り）は両方空**。
ここを間違えると、閉まった門の前に人を立たせる。

**食べどき** — 飲食店だけチェック。**寺社・記念館は全部空のまま**にする。
1つでもチェックすると「時間帯で出方が変わる場所」として扱われる。

## 5. データの信頼性 ★未解決

シードに入れた営業時間は **一般に知られている時間を置いただけの仮データ**。
反映していないもの:

- 季節変動（清水寺の夜間特別拝観、庭園の冬季短縮）
- 定休日・臨時休業
- 最終受付（閉門30分前など）

`closing_soon` の1時間バッファはこれを部分的に吸収するが、**定休日は吸収できない**。
実証実験の前に現地確認が必須。ここがズレると、この仕組みは逆効果になる。
